## 3. Функции, ссылки и копирование

Прогноз заполняется до первого запуска. Для эксперимента 2 необходимо
сохранить исходный результат и отдельно указать результат после исправления.

| № | Прогноз до запуска | Фактический результат | Причина |
|---:|---|---|---|
| 1 | 5, 23 | 5, 23 | В первом вызове два числа складываются. Во втором — строка "2" и число 3 дают конкатенацию "23". |
| 2 | undefined → 16 | 16 | В исходном варианте был пропущен return в теле с {}, поэтому возвращалось undefined. После добавления return value * value функция вернула 16. |
| 3 | 5, true | 5, true | alias — это не копия, а ссылка на тот же объект product. Изменение alias.stock меняет и product.stock. Оператор === сравнивает ссылки. |
| 4 | 7, false, true | 7, false, true | Spread [...products] создаёт новый массив (поэтому false), но объекты внутри остаются теми же (поэтому изменение stock видно в обоих и === даёт true). |
| 5 | 3 8 3, false | 3 8 3, false | Порядок spread важен: {...product, stock: 8} перезаписывает stock на 8. А {stock: 8, ...product} перезаписывает 8 обратно на 3 из product. Сам product не меняется. |
| 6 | Без названия, Без названия, null, "" | Без названия, Без названия, null, "" | Дефолт "Без названия" срабатывает только при undefined. null и пустая строка "" — это валидные значения, они не заменяются. |

**Исправление эксперимента 2:** В исходном коде стрелочная функция square имела фигурные скобки, но не содержала return. В JavaScript при таком синтаксисе результат выражения не возвращается автоматически. Я добавила return value * value;, после чего square(4) стал возвращать 16.

## 4. Модель данных и функции

Поля задачи: объект состоит из 4 полей. id - безопасное целое число больше нуля; title - строка от 1 до 100 символов после trim(); completed - логическое значение (при создании всегда false); priority - строго low, medium или high (по умолчанию medium).
Правила валидации: при создании и изменении строго проверяется тип данных (строки не превращаются в числа). Название не может быть пустым или длиннее 100 символов. Приоритет принимается только из трех разрешенных значений.
Назначение файлов: файл data.js хранит исходные массивы задач; файл task-service.js содержит прикладную логику (9 функций) без вывода в консоль; файл main.js выполняет роль сценария - вызывает функции и выводит результаты; файл checks.js используется для автоматической проверки.
Функции изменения: addTask, setTaskCompleted, renameTask и removeTask не мутируют исходные данные. Они создают новый массив и новый объект только для изменяемой задачи. При успехе возвращают { ok: true, tasks: [...] }, при ошибке - { ok: false, error: "..." }.

**Почему id не равен индексу:** индекс меняется при удалении или добавлении элементов, а id - стабильный идентификатор записи.  
**Почему getTaskStats возвращает число, а не строку с процентом:** число нужно для дальнейших расчетов; округление (toFixed) делается только при выводе.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив и новый объект для изменяемой задачи, остальные записи переиспользуются.
